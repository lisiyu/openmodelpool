## 1. 项目信息

| 字段 | 内容 |
|---|---|
| 语言 | 简体中文 |
| Programming Language | 后端 Go；前端 原生 JS（管理面板 `admin.html` + 配套 `admin-*.js`）；**非 React** |
| Project Name | `omp_admin_domain_binding_guide` |
| 原始需求复述 | 在管理员页面内新增「域名绑定引导」能力，帮助管理员理解/完成「把自己的 OMP 实例绑定到一个自定义域名」这件事。真实运维语境：用户将 OMP 部署在 codespace（.io 节点），并用 **cloudflared 命名隧道**做域名绑定/对外暴露（v4.1.7 已落地该部署形态，`run-omp.sh` 由 supervisor 托管）。因此本功能中的「域名绑定」主要指：把自定义域名通过 cloudflared 隧道 / 反向代理指向 OMP 实例（:8000 管理页 / :8001 网关）。 |
| 关联设计 | §13.4「一键域名绑定功能设计」（全自动创建 Cloudflare 隧道）与本功能**范围不同**，详见第 4 节 Q6 |
| 风格参考 | 复用同项目 `PRD-auto-update.md` 的结构风格（同页面、同类增量功能），内容独立 |

### 1.1 范围基线（v1 需求前提，确定性约束）

- **技术栈约束**：OMP 为 Go 后端项目；管理员页面为 Go 模板渲染的 HTML + 原生 JS（非 React）。每个 OMP 实例拥有独立管理页面。
- **形态取舍（推荐基线）**：v1 以 **形态 A（纯引导/展示）** 为最小可用基线——展示当前访问地址 + 给出绑定步骤指引，**不改变后端逻辑、不自动创建隧道**。形态 B（配置持久化/回显）、形态 C（半自动辅助）作为 P1/P2 后置，是否纳入由第 4 节待确认问题拍板。
- **与 §13.4 的边界**：本功能**不**自动调用 Cloudflare API 创建/管理隧道（那是 §13.4「一键域名绑定」的范围）。本 PRD 只做「引导 + 可选记录」，避免与既有设计的范围重叠。
- **部署现实**：用户实际部署形态为 codespace（.io 节点）+ cloudflared 命名隧道，`run-omp.sh` 由 supervisor 托管；绑定本质是「自定义域名 → 隧道/反代 → 本机 :8000/:8001」。指引须覆盖该现实路径，而非仅讲理论。

> 说明：上述边界为需求基线，实现侧须在此框架内设计；超出边界的设想（如自动调 Cloudflare API、自动改 DNS）不在本 PRD v1 范围，除非待确认问题另有决定。

## 2. 产品定义

### 2.1 产品目标（为什么要做）

自建 OMP 的管理员在把实例通过自定义域名对外提供服务时，往往要自行拼凑 cloudflared 隧道、Nginx/Caddy 反代、DNS 解析等零散步骤，门槛高、易出错、缺少统一入口。本功能在管理员页面内提供「域名绑定引导」：自动展示当前访问地址、给出贴合实际部署形态（codespace + cloudflared 命名隧道 / 反代）的分步绑定指引，并可选记录已绑定域名，将原本分散、依赖外部文档的域名绑定运维收敛为管理页内一处可读、可照做的引导，显著降低自建 OMP 的域名绑定门槛。

| ID | 目标 | 说明 |
|---|---|---|
| G1 | **现状可见（Visible）** | 管理页清晰展示本实例当前的访问入口（管理页/网关/当前访问 URL），并判定「是否已通过自定义域名访问」，让管理员一眼看清现状。 |
| G2 | **步骤可照做（Guided）** | 提供贴合真实部署形态（cloudflared 命名隧道 / 反代 / DNS）的分步指引与示例片段，管理员无需离开管理页即可照做，降低信息搜寻与试错成本。 |
| G3 | **记录可回显（Optional, Recordable）** | （P1 起）允许管理员记录「已绑定域名」并持久化回显，使绑定状态在团队/重启后可见、可追溯（不自动改隧道）。 |

### 2.2 用户故事（管理员视角）

| ID | 角色 | 诉求 | 收益 |
|---|---|---|---|
| US1 | 自建 OMP 的管理员（codespace 部署） | 我希望打开管理页就能看到当前实例的访问地址，并知道「怎么把我的自定义域名绑上来」 | 不必去翻 cloudflared / Cloudflare 文档，按页内指引即可完成绑定 |
| US2 | 多形态部署的管理员（容器/云主机/本地） | 我希望看到针对不同部署形态（隧道/反代）的差异化绑定步骤 | 避免套用错误模板导致 502 / 解析失败 |
| US3 | （P1 可选）需交接/复现的管理员 | 我希望把「已绑定域名」记到管理页，重启或他人接手时能直接看到 | 绑定状态可追溯，减少口头交接遗漏 |

## 3. 技术规范

### 3.1 需求池（Requirements Pool）

> 优先级：P0=必须（Must）/ P1=应该（Should）/ P2=可选（Nice-to-have）
> 形态映射（建议）：P0 ≈ 形态 A（纯引导/展示）；P1 ≈ 形态 B（配置持久化/回显）；P2 ≈ 形态 C（半自动辅助）。最终取舍见第 4 节 Q1。

#### P0（必须 · 最小可用 = 形态 A 纯引导）

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-1 | **展示当前访问地址** | 管理页新增区块展示本实例的访问入口：① 管理页地址（:8000）；② 网关地址（:8001）；③ 当前访问入口（由页面当前 URL 推断，如 `https://xxx.io` 或 `http://host:8000`）。纯前端读取，不依赖新增后端 API（若无法自动获取则回退展示已知/配置地址，见 Q5）。 |
| P0-2 | **绑定步骤引导** | 展示「如何把自定义域名绑定到本 OMP 实例」的分步指引，至少覆盖：① **cloudflared 命名隧道**方式（隧道配置说明、Ingress 指向本机 :8000/:8001、DNS CNAME 指向隧道地址、重启 `run-omp.sh`/supervisor 的提示）；② **反向代理**方式（Nginx / Caddy 指向 :8000 的示例说明）；③ **DNS 解析**说明（CNAME/代理模式注意事项）。内容文本化、示例化，**不执行任何命令、不调外部 API**。 |
| P0-3 | **当前绑定状态提示** | 根据当前访问 URL 的 host 判定：① 若 host 为自定义域名 → 绿色提示「✅ 您正通过自定义域名 <域名> 访问」；② 否则 → 灰色提示「尚未绑定自定义域名，按下方步骤绑定」。判定逻辑纯前端即可完成。 |

#### P1（应该 · 形态 B 配置持久化/回显）

| ID | 需求 | 验收标准 |
|---|---|---|
| P1-1 | **已绑定域名配置持久化与回显** | 管理页提供「已绑定域名」输入框 + 保存按钮；后端将域名持久化（建议落 `config.json` 新增 `bound_domain` 字段），并在管理信息接口（复用 `/api/admin/info` 扩展字段，或新增 `/api/admin/domain`，见 Q3）回显，页面展示已记录域名。保存后刷新页面仍可见。 |
| P1-2 | **域名格式校验** | 对输入的「已绑定域名」做基础格式校验（非空、合法域名格式），非法时给出明确提示，不写入持久化。可达性检测见 P2-1。 |
| P1-3 | **多部署形态差异化提示** | 引导步骤中针对 codespace（.io 节点）、容器、云主机、本地等不同部署形态给出差异化注意事项（如 codespace 需保持实例运行、supervisor 重启命令、`run-omp.sh` 角色），避免套错模板。 |

#### P2（可选 · 形态 C 半自动辅助）

| ID | 需求 | 说明 |
|---|---|---|
| P2-1 | **检测当前隧道公网地址（可选）** | 提供「检测/刷新当前 cloudflared 隧道公网地址」的辅助（若本地可探测 cloudflared 状态），作为半自动辅助。是否探测、探测方式、跨环境可行性见 Q4。 |
| P2-2 | **一键复制配置片段** | 对 cloudflared `config.yml`、Nginx、Caddy 等示例片段提供「一键复制」按钮，降低照做成本。 |
| P2-3 | **可达性状态与解绑** | 保存域名后，可选展示「该域名是否解析可达本实例」的状态（如轮询检测），并提供「解绑/清除已记录域名」入口（仅清记录，不改隧道）。 |

### 3.2 UI 设计稿（管理员页面新增「域名绑定引导」区块）

> **位置建议**：在 `admin.html` 末尾、「🔄 版本更新」卡片（`admin.html:860`）之后，新增独立卡片「🌐 域名绑定引导」——与版本更新同属「管理员运维辅助类」卡片，并列于底部，改动最小、语义一致。
> **备选位置**：配置管理卡片的「公网访问区域」（设计文档 §13.4 所述位置）。若 v1 为纯前端引导、无后端依赖，置于底部运维区更轻量；最终落位由 Q6 / 架构师拍板。

#### A. 默认态（尚未绑定自定义域名）

```
┌─ 🌐 域名绑定引导 ──────────────────────────────┐
│  当前访问地址：                                  │
│   · 管理页 :8000   http://<host>:8000           │
│   · 网关   :8001   http://<host>:8001           │
│   · 当前入口       https://xxx-8000.preview.app │
│                                                  │
│  [⚪ 尚未绑定自定义域名，按下方步骤绑定]          │
│                                                  │
│  ▸ 如何绑定自定义域名（点击展开）                │
│    ① Cloudflared 命名隧道（推荐，codespace 场景）│
│       - 在 Cloudflare 创建命名隧道，Ingress 指向 │
│         本机 :8000（管理页）/ :8001（网关）      │
│       - DNS 添加 CNAME 指向隧道地址              │
│       - 重启 run-omp.sh（supervisor 托管）       │
│    ② 反向代理（Nginx / Caddy）→ :8000           │
│    ③ DNS 解析说明（CNAME / 代理模式注意事项）    │
│  [P2] 一键复制配置片段                           │
└──────────────────────────────────────────────────┘
```

#### B. 已通过自定义域名访问 / 已记录域名（含 P1）

```
┌─ 🌐 域名绑定引导 ──────────────────────────────┐
│  当前访问地址：                                  │
│   · 管理页 :8000   http://<host>:8000           │
│   · 网关   :8001   http://<host>:8001           │
│   · 当前入口       https://api.my-node.com      │
│                                                  │
│  [✅ 您正通过自定义域名 api.my-node.com 访问]     │
│                                                  │
│  已绑定域名（记录）：api.my-node.com  [解绑]      │
│  ┌─ 输入框 ────────── [保存] ─┐                  │
│  [P2] 域名可达性：● 可达 / ○ 检测中             │
│                                                  │
│  ▸ 如何绑定/更换自定义域名（点击展开） …         │
└──────────────────────────────────────────────────┘
```

- 状态配色：已绑定/可达=绿（✅/●），未绑定/检测中=灰（⚪/○），失败=红（❌）。
- 引导步骤区默认折叠，点击展开；示例片段纯展示，复制为 P2-2。
- 输入框、保存、解绑仅在纳入 P1/P2 时出现；纯形态 A 时隐藏，仅保留展示与引导。

## 4. 待确认问题（Open Questions）

| # | 问题 | 风险 / 影响 |
|---|---|---|
| Q1 | v1 仅做**纯引导（形态 A）**，还是同时含**配置持久化（形态 B）/ 半自动辅助（形态 C）**？ | 影响整体范围与是否引入后端。推荐 A 为 P0 基线、B/C 后置，以控制范围、快速落地 §19.6 P0；若一次性做 B/C 则工作量与后端依赖显著上升。 |
| Q2 | 若做 B（配置持久化），域名记录**存哪**？`config.json` 新增 `bound_domain` 字段？还是复用现有配置结构？是否需走现有 `encryptor`（注意 bound_domain 本身非密钥，但若关联隧道信息则可能需要加密）？ | 影响 P1-1 的数据结构与安全设计；落点不一致会导致与现有配置加载逻辑冲突。 |
| Q3 | 是否**需要后端 API**？纯引导（A）无需后端；若做 B 是新增 `/api/admin/domain` 还是复用 `/api/admin/info` 扩展字段？鉴权是否复用现有管理员鉴权？ | 影响 P1 实现复杂度与接口设计；纯前端方案可零后端改动，风险最低。 |
| Q4 | 是否**检测 cloudflared 隧道实际公网地址**（P2-1）？本地进程探测 vs 远程 API？codespace/容器环境下 cloudflared 是否与 OMP 同机可探测？ | 影响 P2 范围与可行性；跨环境/容器内探测可能不可行或需额外权限，可能降级为「提示手动查询」。 |
| Q5 | 「当前访问地址」**如何获取**？纯前端 `window.location` 推断是否足够？经反代/Nginx 后 Host 头是否准确？多网卡/多入口（:8000 与 :8001）展示策略？ | 影响 P0-1 的准确性；纯前端方案在反代后会丢失真实公网地址，可能需后端回传 `Host`/请求头。 |
| Q6 | 本功能与**设计文档 §13.4「一键域名绑定」（自动创建 Cloudflare 隧道）**的关系？本 PRD 明确只做「引导/记录」、不自动调 Cloudflare API，是否与未来自动绑定功能共存/互补、UI 落位是否同区？ | 影响范围边界与未来衔接；需确认本功能不与 §13.4 重叠，避免重复建设与冲突。 |

## 5. 交付范围小结（给主理人转发用）

- **类型**：简单 PRD（默认格式，无竞品/市场分析）｜增量于现有管理员页面（建议置于「🔄 版本更新」卡片之后）。
- **核心目标**：降低自建 OMP 的域名绑定运维门槛——在管理页内展示当前访问地址、给出贴合真实部署（codespace + cloudflared 命名隧道 / 反代）的分步绑定指引，并可选记录已绑定域名。
- **范围基线**：Go 后端 + 原生 JS 管理页（非 React）；v1 推荐 **形态 A 纯引导**为最小可用；**不**自动调 Cloudflare API（与 §13.4 自动绑定区分），避免范围重叠。
- **P0（必须）**：P0-1 展示当前访问地址；P0-2 绑定步骤引导（cloudflared 命名隧道 / 反代 / DNS，纯展示不执行）；P0-3 当前绑定状态提示（是否已通过自定义域名访问）。
- **P1（应该）**：P1-1 已绑定域名配置持久化与回显；P1-2 域名格式校验；P1-3 多部署形态差异化提示。
- **P2（可选）**：P2-1 检测当前隧道公网地址；P2-2 一键复制配置片段；P2-3 可达性状态与解绑。
- **待确认（关键风险）**：形态取舍 A/B/C(Q1)、域名配置落点(Q2)、是否需后端 API(Q3)、是否探测隧道公网地址(Q4)、当前访问地址获取方式(Q5)、与 §13.4 自动绑定功能的关系与落位(Q6)。
- **背景**：本功能为 §19.6 P0 标记的待实现项；完成后以 LOOP 模式继续检查并实现其他未落地功能。
