## 一、项目定位与现状速览

OpenModelPool（OMP）是一个**聚合多家大模型供应商 API、提供 OpenAI 兼容统一网关**的自托管项目，定位"开放模型池"——任何个人/组织都能把自有额度接入共享，让没钱的人也能用上 AI。已部署 `openmodelpool.io`（Cloudflare 隧道 + GitHub Codespaces）。

**技术取向**：单一 Go 二进制、零外部依赖、`package main` 单包（166 文件）、原生 JS 内嵌前端。设计哲学是"一个可执行文件跑全栈"，这与公益"低门槛部署、可审计、可移植"高度契合。

**成熟度总评（公益视角）**：

- 网关/代理/多用户/联邦认证/免费池等"可用骨架"已扎实；
- 但**真正体现公益核心价值的能力（去中心化抗审查、贡献透明、社区治理）几乎全是空壳或伪实现**；
- 已于 2026-08-08 Phase 0 修复 2 个上线即存在的真实 Bug（心跳/区域同步空转），并将贡献账本从伪 IPFS 诚实化为本地内容哈希存储、删除死代码 `ipfs_ledger.go`；仍存在少量文档与代码背离（见 2.5，部分已在本报告修订中纠正）。

## 三、按"纯公益"铁律重新审视未实现项

商业模式下，贡献账本/IPFS/治理常被用于"积分经济、代币化、平台抽成"——这些在公益下**必须剔除**。公益视角下，这些能力应被重新定义为：

1. **贡献账本 → 公益透明度底座**：不是"积分换钱"，而是"谁的额度被谁用了、公益算力如何分配"完全公开可审计，让捐助者/志愿者看到真实影响。
2. **去中心化（DHT/IPFS/真 P2P）→ 抗审查与永续**：公益项目最怕被单一实体关停或挟持。真正的分布式发现 + 内容寻址 = 单点失效免疫。
3. **社区治理 → 价值共识而非利益分配**：模型白名单、节点准入由社区共治，避免少数人独裁决定"谁能享受 AI"。
4. **免费池/低门槛 → 普惠核心**：让无支付能力者（学生、公益组织、发展中国家）零成本获得 AI 能力。
5. **自动更新/一键部署 → 公益扩散力**：普通人也能跑节点，网络效应才起得来。

**结论**：当前"空壳/伪实现"的恰是公益最该做实的部分；而"商业模式导向"的积分经济则应主动放弃。这是规划演进方向的底层逻辑。

## 四、公益演进方向规划（路线图）

按"公益价值 × 技术就绪 × 实现成本 × 抗风险"四轴评估，分四个阶段推进。

### 阶段 0：可信度夯实（公益的地基，先做）
**目标**：修掉"伪实现"和真实 Bug，让项目对贡献者/使用者诚实。

- [ ] **修真实 Bug**：`stubs.go:52` 心跳循环改为 `for{select{}}`；区域同步要么实现要么明确移除并删 TODO。
- [ ] **去伪实现**：贡献账本的 IPFS 客户端要么接真实节点，要么降级为"可验证哈希链 + 多节点冗余副本"并**如实命名**（去掉 "IPFS-backed" 误导）。
- [ ] **文档对齐**：README/design 中未兑现的 "Phase 2" 承诺改为"规划中"或删除；WAF 章节更正为"已实现、默认关闭"。
- [ ] **补核心测试**：`network.go`/`gossip.go`/`federation.go`/`contribution_ledger.go` 等大模型**缺同名测试**，公益项目靠社区贡献，测试缺失会劝退贡献者。
- [ ] **格式治理**：全仓 166 文件 CRLF 导致 `gofmt` 全未格式化，统一转 LF 降低贡献门槛。

> 公益价值：诚信是公益第一资产。一个"号称去中心化实则空壳"的项目会反噬信任。

### 阶段 1：真实去中心化与抗审查（公益核心)
**目标**：把"去中心化"从名词变成动词。

- [ ] **DHT 接真实网络层**：在内存 K-Bucket 基础上实现 Kademlia 迭代查找（FIND_NODE/FIND_VALUE + α 并发），让节点发现不再强依赖中心 registry。
- [ ] **内容寻址账本**：贡献记录用内容哈希（CID 风格）链，多节点冗余存储；短期用"N 个联邦节点各存一份 + 哈希校验"替代真 IPFS，长期再接轻量 IPFS（如 Kubo HTTP API 或手术刀式 bitswap）。
- [ ] **联邦自愈**：节点掉线后信任池自动收敛，不依赖人工重新加 Peer。
- [ ] **离线可读**：本地缓存最近一次全量信任池/模型目录，断网仍能服务已授权请求。

> 公益价值：单点失效免疫 = 公益服务永续。对抗审查、抗关停的核心保障。

### 阶段 2：贡献透明与社区共治（公益信任)
**目标**：让"公益算力从哪来、到哪去"人人可查，让社区决定规则。

- [ ] **公开审计仪表盘**：基于真实账本，前端展示"各节点贡献/消耗量、免费池使用分布"，数据可导出验证。
- [ ] **社区共治设计**：如需节点准入 / 模型白名单多签共治，从零设计治理层（原 `initGovernanceManager` 死代码已于 2026-08-08 删除）。GitHub 提案 + Gossip 投票 + Ledger 记录的治理模型可重新落地。
- [ ] **跨联邦算法治理落地**：把已 defer 的"跨联邦 propose/vote/gossip"补完，让参数（如免费池比例、共享上限）由社区民主决定，而非单节点权威。
- [ ] **贡献者荣誉体系（非经济激励）**：用透明榜单/徽章代替积分变现——公益不需要"代币"，需要"被看见"。

> 公益价值：透明度 + 共治 = 捐赠者与志愿者的信任来源，也是对抗"中心化滥权"的结构性解。

### 阶段 3：普惠深化与低门槛扩散（公益可达性)
**目标**：让更多"无支付能力/无技术能力"的人用上、跑起 OMP。

- [ ] **免费池增强**：增加教育专属额度、公益组织认证额度、零门槛匿名访问（限免额度内）。
- [ ] **一键部署 + 一键更新完善**：把 auto-update 的 P1 跨环境广播做实部并补测试；提供图形化部署引导（含 Cloudflare 隧道/家庭宽带 NAT 场景）。
- [ ] **多语言 / i18n**：公益普惠全球，前端抽离文案做国际化（至少中英）。
- [ ] **无障碍（a11y）**：管理面板满足基本键盘/读屏可达。
- [ ] **隐私与数据主权**：端到端加密对话历史、零日志可选模式、本地优先——公益项目更该保护弱势用户隐私。

> 公益价值：技术再好，普通人跑不起来、用不起，就不是公益。

### 阶段 4：教育科研与开放生态（公益外溢)
**目标**：把 OMP 变成公共知识基础设施。

- [ ] **开放评测基准**：基于聚合的多模型，提供公开、可复现的模型能力评测数据集与榜单。
- [ ] **教学案例与沙箱**：为高校/训练营提供"如何自建 AI 网关"的教案与最小实验环境。
- [ ] **开放插件/扩展协议**：第三方可贡献模型适配器、公益场景 Prompt 库，社区共建。

> 公益价值：从"给鱼"到"给渔"，提升整个社会的 AI 素养。

## 六、唯一下一步建议

**先花一个迭代做"阶段 0：可信度夯实"**——具体就三件事：
1. 修 `stubs.go:52` 心跳循环（一行级改动，但影响联邦健康度）；
2. 把贡献账本的 "IPFS" 伪客户端改名/降级为"多节点哈希冗余"，消除误导；
3. 对齐 README/design 文档中未兑现的 Phase 2 承诺。

这三件事零新功能、纯"诚信修复"，却直接决定公益项目能否赢得社区信任。**建议从这三件开始，而不是先追去中心化的宏大功能**——一个诚实的 v4.3.16 比一个吹嘘去中心化的空壳更有公益价值。
