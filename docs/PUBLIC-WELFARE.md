# OpenModelPool — 公益优先的 LLM API 聚合网关

> 一份写给"为什么值得跑一个节点 / 为什么值得贡献算力"的说明。所有描述均对应已落地的代码，不夸大、不画饼。

## 它是什么

OpenModelPool 是一个**开源、单二进制、自托管**的 LLM API 聚合网关：

- 同时兼容 **OpenAI `/v1/chat/completions`** 与 **Anthropic `/v1/messages`** 两种格式，现有 SDK（OpenAI / Anthropic / LangChain 等）改个 base URL 即可直连，无需改业务代码。
- 内置**负载均衡 + 智能路由 + 故障转移**（按节点评分选优，上游失败自动换下一个可用渠道）。
- 内置**按 API 密钥的配额管理**，以及一套**公益配额分配引擎**（Guest Key Pool / Public Key Pool 比例可调）。

## 公益优先，无商业模式

这是与同类项目的根本分野：

- **不做积分、不做代币、不做抽成。** 没有任何可交易的通证经济。
- 节点运营者把自有算力按自己设定的比例，分给"访客池"与"公益池"，供社区免费使用。
- 账本公开可审计，任何人都能核验"算力从哪来、到哪去"。

对比商业网关：LiteLLM / One API / New API 功能成熟但带有商业版、在线支付或企业收费墙；OpenRouter 对信用卡消费收 5.5% 平台费。OpenModelPool 全程**零费用、零代币、账本公开**。

## 去中心化联邦（抗审查 / 永续）

- 节点之间通过 **STUN/NAT 类型探测 + UDP 打洞**建立直连通道，并以 **DHT（Kademlia）** 互相发现，不依赖单一中心。
- 贡献账本在联邦内**多节点各存一份**，以内容哈希（sha256）做存证；后台**每 60 秒自动对账**，缺失记录自愈、分歧记录仅告警不覆盖——任何单节点丢失都不会让账本消失。

## 透明（trust through auditability）

- 贡献记录以内容哈希存证（`ContentHashStore`，`sha256:` 前缀），剔除节点专属签名后仍可跨副本比对业务摘要。
- `GET /api/admin/ledger/transparency`：按节点 / 按模型聚合"贡献了哪些算力"，并校验交易链完整性。
- 贡献明细与完整账本可 **CSV / JSON 导出**（`GET /api/admin/ledger/export`），供研究者直接使用。

## 公益额度闭环（贡献 → 免费配额）

这是把"去中心化"真正跑起来的关键一环（P2-3）：

- 某节点向公益池**捐赠算力**，其贡献会按 **1:1 等额**累积为"免费配额 entitlement"——**零手续费、不通胀、不可交易**，只是一笔透明记账："贡献者 X 捐了 N token → 有权从公益池免费用 N token"。
- `GET /api/admin/ledger/contribution-quota`：每个贡献者的"贡献量 ↔ 赚得免费配额"随时可查。
- 消费侧按贡献者身份从公益池抵扣配额（P2-3(ii)）将在补齐用户/身份模型后加法式接入。

> 这与 Petals"贡献 GPU 换取社区加速/权益"的思路同源，但发生在 API 网关层，且全程公益、无货币。

## 架构分层（一句话）

```
网关层   兼容端点 + 路由/负载均衡/故障转移 + 按密钥配额
联邦层   DHT 发现 + NAT 穿透/直连 + 账本跨节点复制与对账
账本层   内容哈希存证 + 多副本冗余 + 自动自愈 + 公益额度闭环
```

## 如何运行（一行部署）

```bash
docker compose up -d        # 数据持久化在命名卷 omp-data，默认监听 :8000
docker compose logs -f      # 查看日志
```

公网暴露推荐走 **Cloudflare Tunnel / 自有反代**，而非直接暴露 8000 端口。详见仓库 `docker-compose.yml` 与现有部署文档。

## 免费池开箱即用（任意节点 + 硬编码公钥）

OpenModelPool 内置一个**社区免费池**：一批匿名、无需密钥的免费 LLM API（由 `awesome-free-llm-apis` 列表自动同步，默认开启）。任何人**无需注册、无需自有 API key**，只要知道：

- **任意一个 OpenModelPool 节点的地址**（如 `https://openmodelpool.io`），加上
- **全局硬编码公钥** `sk-openmodelpool-com-github-lisiyu-openmodelpool-public-key-v1`

即可直接使用免费池，把节点的 base URL 指过去就行：

```bash
curl https://<任意节点>/v1/chat/completions \
  -H "Authorization: Bearer sk-openmodelpool-com-github-lisiyu-openmodelpool-public-key-v1" \
  -H "Content-Type: application/json" \
  -d '{"model":"<模型名>","messages":[{"role":"user","content":"你好"}]}'
```

### 免费额度的归属模型（个人自用 vs 公共池）

这是 OpenModelPool 的核心运行方式，也是它区别于商业网关的关键：

- **人人开箱即得免费额度**：只要装了 OMP 客户端并开启免费池自动同步（默认开启 `free_pool_auto_sync=true`），就**自动获得预设免费上游的模型可访问额度**——**即使没添加任何自有上游，也能自由使用**。
- **不强制共享**：节点默认处于**个人模式**，免费额度（以及你自己的上游额度）在个人模式下**只供你自己消费，不进联邦公共池**。系统**绝不强制**你加入共享网络。
- **加入即变公共池**：当你**主动加入共享网络**时，你的免费上游与自有额度才成为**公共池资源**，为社区提供更多出口与并发额度——因为免费服务商通常限制并发与总额度，**更多出口即意味着更多可用资源**。
- **无额度也能做网关**：即使你没有任何额度可贡献，加入共享网络后仍可**转发流量、作为 gateway / 出口节点**——这也是社区治理的一部分，出口本身即是一种贡献。

要点：

- **任意节点都行**：免费池是社区公共资源，不绑定任何节点。即使该节点处于个人模式，公钥也只触达"社区免费池"，**绝不会暴露节点运营者自己的私有付费渠道**——隐私与公益在此分离。
- **可用模型随时查**：`GET /v1/models`（带同一公钥）返回当前免费池已同步到的模型清单（随上游列表动态更新）。
- **防滥用而非防人**：按治理哲学"默认善意、只防恶意滥用"，对公钥请求做**按客户端 IP 的四层配额限流**（全局日限额 / 单 IP 日限额 / 小时窗 / 单模型限额），避免单个滥用者垄断免费池，而正常使用者几乎无感。
- 想用更强模型或更高额度？把自有 provider key 填进节点即可，节点会自动把"用不完的额度"按比例分给公益池——这正是它的运行方式。

## 社区共治（贡献者治理）

节点准入、模型白名单、参数调整等公共决策，由**贡献者共治**——投票资格属于"向公地贡献过算力"的节点（"contributors govern"）。提案与批准都写入**追加式、哈希链式的共治账本**，整段历史可校验、防篡改；一项提案在**超多数（≥2/3 合格投票者）** 同意后生效。

治理哲学是"**默认善意**"：系统只防**滥发提案**（每节点最多 5 个未结提案），**不做惩罚、不扣分、不信任评分**——不同意见不会被清算，只是没达到通过门槛。这与商业平台的"质押/罚没"治理模型截然不同。

- **默认不强制加入**：节点默认处于个人模式，系统**绝不强制**你加入共享网络；只有当节点仍有**闲置的自有额度**时，才在后台日志与 `/api/network/status` 状态接口给出一条**温和的软提醒**（鼓励而非胁迫）——建议把闲置额度贡献为社区公共池资源。不加入也完全可用（仅自用 + 社区免费池）。
- **加入是加法不是义务**：加入共享网络能带来更多出口、更多并发额度，并解锁"贡献→公益配额"闭环；但不加入、甚至没有任何自有额度，也都可以作为 gateway 转发流量参与社区。

## 仍在进行（诚实标注）

- 直连 UDP 通道当前承载**信令与链路建立**，实际请求负载走 UDP 自建协议为后续工作（P2）。
- 消费侧按身份抵扣公益配额（P2-3(ii)）待补齐用户/身份模型后加法式接入。
- **已落地（2026-08-09）**：免费额度归属模型（个人自用 vs 公共池）、默认不强制加入共享网络、闲置额度软提醒、无额度也能做 gateway/转发——见上「免费额度的归属模型」「社区共治」两节。
