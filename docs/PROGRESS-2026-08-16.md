### 2. P1-2b-2(iv) UDP 直连数据承载协议

- **新增 `udp_bearer.go`**
  - `UDPDataBearer`：在已打通的直连 UDP 链路上自建 请求/应答 协议。帧布局固定 27 字节头（magic `OMP2` 4 / typ 1 / reqID 16 / fragIndex 2 / fragTotal 2 / payloadLen 2）+ payload。envelope 帧（jsonLen 4 + JSON meta + 首片）+ `B` 分片（1400 字节/片适配 MTU）。
  - `HandleInbound`：单 socket 读者 `udpRecvLoop` 转交；panic-safe（recover 包裹，绝不拖垮 STUN/打洞）；按 `Q`/`S`/`B` 分流、按 reqID 重组。
  - `onComplete`：响应全量重组后才经 `ch` 投递等待者；请求侧 `go serveReq` 经既有 `relayDispatchHandler` 派发，回写 `S` 帧。
  - `RelayOverUDP(w, r, peer, restPath, body, hop)`：`directLinkMgr.HasDirect` 命中时优先走 UDP；**响应重组完才写客户端，任何失败（超时/分片缺口/解码错）返回 false 干净回退 HTTPS 反向代理，无半包**；流式（`stream:true`）请求不承载、回落 HTTPS 保留 token 流式；复用既有 ed25519 relay 转发签名（`signRelayForward`/`headerRelaySig`/`headerRelayTs`），不引入新信任模型。
  - **关键修复（实现期发现）**：`sendFrames` 原先用链式 `append` 在预分配切片上构造帧头，因切片容量足够时原地写入、**前序字节（含 magic）被后续 append 静默覆盖**，导致接收端 magic 校验失败、20s 超时。改为显式 `make` + `copy` + `binary.BigEndian.PutUint16` 构造，消除一切别名风险。
- **`nat_traversal.go`**：`udpRecvLoop` 在 STUN 分支后增 `OMP2` 帧转交 `udpDataBearer.HandleInbound`；`ensureDirectLinkMgr` 建 `directLinkMgr` 后若 `udp_data_bearer_enabled!="false"` 则建 `udpDataBearer` 绑共享 `natMgr.udpConn`。
- **`network_relay.go`**：`relayToRemote` 在 `directLinkMgr.HasDirect(entry.NodeID)` 且 `udpDataBearer!=nil` 时调 `RelayOverUDP`，返回 false 则告警并回退 HTTPS relay。
- **`nat_punch_loop.go`**：新增 `RegisterDirectLink(nodeID, addr)`（nil 安全、幂等）——已知/管理员固定直连地址可直接登记，不强制走打洞握手；测试用它建立直连先决条件（`Ingest` 仅在存在 punch session 时记录链接，纯 `Ingest` 不生效，故测试原 setup 漏建链接致 `RelayOverUDP` 立即 false）。
- **`udp_bearer_test.go`**（3 用例 PASS）：`TestUDPBearer_RelayRoundTrip`（回环 relay + Authorization 剥离验证）、`TestUDPBearer_RelayLargeBody`（50KB 分片重组）、`TestUDPBearer_StreamingFallsBack`（流式回落）。
