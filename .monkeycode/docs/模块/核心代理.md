# 核心代理

OpenAI/Anthropic API 兼容网关，接收客户端请求并路由到最优上游 Provider。

## 结构

```
核心代理/
├── server.go               # HTTP 路由注册、HTTPS 服务器
├── handlers.go              # 网关入口、Provider 测试
├── client.go                # 上游 AI Provider 客户端（5 种类型）
├── anthropic_api.go          # Anthropic Messages API 兼容层
├── provider.go              # ProviderManager（CRUD + 路由排序）
├── providers.go              # 35 个预设 Provider 定义
├── token_estimator.go        # Token 估算（上游 usage + 本地字符计数）
├── pricing_impl.go           # 模型定价表
└── platform_adapter.go       # 协议翻译层（RequestIR）
```

## 关键文件

| 文件 | 目的 |
|------|------|
| `handlers.go` | 网关入口 `handleGatewayRequest()` → `handleChatCompletions()` |
| `client.go` | 上游请求核心：`doNonStream()`/`doStream()` + 5 种 Provider 适配 |
| `provider.go` | Provider CRUD、路由排序（priority/cheapest/fastest/auto）、多 Key 选择 |

## 请求处理流程

1. **认证**: `withProxyAuth` 识别 Key 类型，设置 `X-Request-Owner`/`X-Request-Role`
2. **WAF**: 四层检查（IP 封禁/黑名单/UA/速率/路径）
3. **速率限制**: 全局 QPS + 每 Consumer QPS
4. **网关决策**: 检查是否有远程节点更优（`routeTable.SelectBestNode()`）
5. **Provider 选择**: `pm.OrderedCandidates(model, routingMode)` 排序候选
6. **Fallback 链**: 逐个尝试候选 Provider，流式请求在数据已发送后不可重试
7. **用量追踪**: `tracker.RecordWithAccessType()` 记录延迟/Token/成功/失败

## 5 种 Provider 适配器

| 类型 | 函数 | 描述 |
|------|------|------|
| `openai_compatible` | `openaiNonStream()`/`openaiStream()` | 标准 OpenAI API |
| `anthropic` | `anthropicNonStream()`/`anthropicStream()` | Anthropic Messages API |
| `sider` | `siderNonStream()`/`siderStream()` | Sider.ai Web Session |
| `web_session` | `webSessionNonStream()`/`webSessionStream()` | 通用 Web Session |
| `coze` | `cozeNonStream()`/`cozeStream()` | Coze 对话 API |

所有适配器均接收 `ctx context.Context` 参数，客户端断连时自动取消上游请求。

## 依赖

**本模块依赖**:
- `middleware.go` — 认证/速率限制中间件
- `tracker.go` — 用量追踪
- `config.go` — 路由模式配置

**依赖本模块的**:
- `relay.go` — 中继请求使用 `doNonStream()`/`doStream()`
- `admin.go` — Provider 管理使用 `ProviderManager`
